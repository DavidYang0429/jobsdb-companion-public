# AI 定制错误恢复验证（2026-10-16）

## 问题与原因

用户看到“总结缺少事实来源”，无法判断应修改哪些资料。代码中该报错实际检查模型的总结引用，不等于用户填错简历。同时，旧校验没有把用户已填写的个人总结、技能、语言或签证信息作为可引用的事实；提示样例还提供了空引用和占位经历 ID，容易产生不能通过校验的结果。

## 实现

- 新增有内容的事实目录，把已有个人总结、技能、语言、签证、教育、经历及要点作为明确来源发给模型。提示样例使用真实 ID；只有个人总结或技能也能作为总结依据。
- 空资料在请求模型前提示，包含真实资料填写示例、“保存主简历”以及返回原岗位的入口。
- 模型遗漏或编造引用仍拒绝采用。提示明确说明属于模型生成问题，提供重新生成或手工制作，不让用户修改内部编号、不静默补配引用。
- 模型新增／重复技能会列出具体名称。数字提示会指出总结或某公司某条要点，以及需要核对的数字；核对总结数字时只使用实际引用资料，不从版本号或无关字段寻找依据。
- 错误卡片在 AI 操作处保留并取得焦点；导航至资料／设置后可以返回原岗位。手工入口使用已保存主简历，失败结果不写成新简历。
- 原文对照补齐教育、技能、语言及签证信息，并把总结来源呈现为真实原文，移除原始来源 JSON。
- 网络、超时、取消、Key、额度、输出格式、资料过期和岗位引用问题提供明确恢复步骤。不会自动发起重试。

## 验证

自动化覆盖：

- 总结来源可使用已有个人总结、技能、语言和签证；联系信息或空白技能不能充当可定制内容。
- 空资料不发模型请求；有效事实目录和真实示例进入提示。
- 缺失／未知引用仍失败，提示区分模型责任且不展示无效内部 ID。
- 数字错误带位置、数字和修正步骤，修正后可通过；无关字段或元数据的数字不会被当作依据。
- 新增及重复技能的具体名称出现在提示中。
- React 集成验证真实 App：资料不足 → 主简历编辑页 → 原岗位；模型失败 → 用户主动重试一次 → 手工简历工作室。没有自动重试、没有保存不合规结果。
- 原文对照显示实际教育／技能与总结参考资料，不显示来源编号或原始 JSON。

内置浏览器使用独立模拟页面检查卡片布局、步骤和操作按钮。该页面明确标注不调用模型，位于忽略目录 .local-test，未加入生产构建入口；真实用户数据和 Key 没有被修改或用于请求。

构建检查包含 TypeScript、生产包、Manifest、图标和 PDF 字体。原有存储、GAS、同步、采集、模型连接及 PDF 回归继续执行，最终 10 个测试文件、69 项测试全部通过；生产构建通过。

真实模型是否每次正确遵循提示仍需用户重载扩展后实测；此次不把模拟响应测试当作真实模型通过证明。
