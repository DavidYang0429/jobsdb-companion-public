# 用户测试修复：PDF 下载和模型反馈（2026-10-16）

## 问题与改动

1. 手工简历原来只有 window.print，没有直接生成下载文件；内置浏览器中的系统打印流程会阻塞页面。新增独立“下载 PDF”，对已保存快照在本地生成 A4 矢量文字文件，“打印…”作为备用入口保留。未保存时明确提示先确认事实并保存。
2. 原来 API 连通性成功仅提示“当前模型连接成功”。现在测试冻结本次设置，返回 provider、requestedModel、responseModel，在可见结果区及提示中展示服务商和模型。Gemini 读取响应顶层 modelVersion，DeepSeek 读取顶层 model；没有元数据时明确提示，不能拿请求名称冒充服务端返回名称。

没有新增后端、自动换模型、自动收费重试或额外 Key 读取。没有使用用户真实 Key 发起测试。

## 具体文件

- src/services/resumePdf.ts：下载生成、自动换行、显示／排序／分页、安全文件名、Unicode 字体覆盖检查。
- src/ui/ResumeWorkspace.tsx：下载入口、生成状态、保存前提示，保留原生打印。
- public/fonts/pdf-v1：离线 TrueType 及来源说明；许可证仍随产物分发。
- src/types/schema.ts：兼容旧备份的可选 layout.pdfExportVersion，新保存记录为 pdf-v1。
- src/services/llmAdapter.ts：保留成功请求实际返回的模型元数据；JSON 与错误处理继续有效。
- src/ui/SettingsPanel.tsx：持久可见的测试结果，失败也明确显示本次请求的服务商／模型。修改 Provider、模型或 Key 清除旧结果，测试中冻结输入。
- vite.config.ts：预构建动态导出依赖，避免开发环境第一次点击下载时发生依赖优化重载。
- scripts/check-build.mjs：检查生产包三个 TrueType 文件签名。

### PDF 文件检查

使用本地实际字体生成测试文件，以 pypdf 检查文字提取和字体嵌入；用 Poppler 渲染并检查页面。

发现并修复了两个仅做构建或 JSON 检查无法发现的问题：

- 字体裁剪可能导致“文字能提取，但页面缺字”。最终使用完整嵌入，英文 Inter；中文及混合文字 Noto，保留离线资源。
- 某些字体默认排版特性会让日期分隔符触发替代数字字形，影响文本提取。导出固定关闭这些替代／竖排／连字特性，复核 2024、2025、数字 2 和中英文文本正确。未改写源简历中的日期或业绩数字。

六个语言／页数样本都检查了年份、技能与正文；额外混合文本样本覆盖用户界面中的日期写法。QA 文件位于忽略目录 .local-test/pdfs，不属于用户简历库。

完整嵌入会增大中文 PDF（约 4～6 MB）；纯英文使用较小的 Inter。它避免缺字，但不代表所有 ATS 都已实测。直接 PDF 的排版由固定版本导出器生成；需要浏览器原生 CSS 排版时仍可用“打印…”。

仅使用 Codex 内置浏览器，打开已保存的虚构 Demo Candidate 历史简历，点击“下载 PDF”，观察到浏览器下载事件并取得实际文件。最终文件为：

`/path/to/downloads/Demo Candidate_Business Analyst - Data & AI Governance (18-month contract)_Cathay Pacific Airways Ltd (3).pdf`

该文件实际检查了英文姓名、中文说明、原文要点、数字 2、2024／2025 年份、A4 页和页面渲染。没有依赖系统打印对话框。早期尝试下载文件仍在下载目录，未擅自删除；以最终修复后的下载结果为准。

### 构建与边界

运行 npm run build，包含 TypeScript、生产包、Manifest、图标与 PDF 字体检查。非阻塞提示仍有 Zod PURE 注释和导出依赖 chunk 大小；导出库已动态加载，不占用初始页面加载路径。

真实模型账号仍待用户自行配置连通性验证，当前模型反馈通过模拟成功／缺字段响应和界面测试验证。Chrome 扩展真实加载与 GAS 外部联调仍沿用首版待验收状态，没有把网页预览当作扩展运行证明。
