# 插件侧栏宽度与显示修复（2026-10-16）

## 原因与改动

原侧栏职位表需要横向滚动；进入简历工作室后，App 返回的界面没有保留 panel-mode，导致侧栏样式失效。A4 纸固定 210mm 宽，也没有对窄显示区域缩放。

本次调整：

- 侧栏内容 width:100%、max-width:520px，小于上限时随实际可用宽度收缩，不设会撑开页面的最小宽度。
- 同一职位表在侧栏以带字段标签的卡片排列，保留进度修改、简历和同步状态；全屏仍显示表格。
- 导航、按钮、筛选、表单、历史记录和弹窗按窄宽度换行，长职位名／链接可断行。
- 简历工作室保留侧栏模式，顶部操作可见，提供“编辑简历／查看预览”切换，两个视图共用当前草稿，不在切换时保存或重建草稿。
- ResponsiveResumePreview 用 ResizeObserver 根据容器和纸张实际尺寸计算显示缩放及占位高度。只缩小屏幕显示，原始纸张仍为 A4；打印样式明确取消缩放和屏幕占位尺寸，直接 PDF 导出数据与生成器未改。

限制的是插件内容。当前官方 [Side Panel API](https://developer.chrome.com/docs/extensions/reference/api/sidePanel) 未提供外框宽度设置参数，本次不声称锁定 Chrome 宿主侧栏宽度。

## 内置浏览器验证

仅使用 Codex 内置浏览器，未改变用户的主简历、岗位状态、Key 或表格配置。

| 视口／页面 | 观测结果 |
| --- | --- |
| 390px 侧栏岗位页 | document.clientWidth=390、scrollWidth=390，职位表改为卡片，没有页面横向溢出 |
| 390px 侧栏预览 | 预览约缩放为 46%，画面宽约 366px；frame 与纸张显示宽度一致，A4 全幅可见 |
| 320px 侧栏预览 | document.clientWidth=320、scrollWidth=320，预览宽约 296px、约 37% |
| 320px 岗位卡片 | 卡片宽 266px，显示投递进度、简历、同步、录入时间标签，进度选择器可见 |
| 320px 设置页 | 页面宽 320px，表单输入的右边界均在视口内 |
| 320px 录入弹窗 | 弹窗宽 300px，左 10px、右 310px，高度限制在视口内，内容可纵向滚动 |
| 900px 侧栏页面 | 内容实际宽 520px，页面 scrollWidth=900，不再把内容拉满较宽面板 |
| 1440px 全屏工作台 | 没有 panel-mode，main 宽 1212px，table 保持 table 布局，页面无横向溢出 |

检查后恢复了临时视口设置。预览缩放范围是本次样本值，长简历高度会由观察器重新计算，不把这些值硬编码到布局。

## 自动化与构建

新增 panelLayout.test.tsx，分别验证侧栏和全屏打开历史简历：侧栏上下文保留，全屏独立；侧栏切换预览后返回编辑，未保存的姓名仍保留，历史快照不被改写。

原有 AI 错误恢复、存储、采集、同步、GAS、模型反馈及 PDF 回归继续执行。最终 11 个测试文件、71 项测试通过。生产构建包含 TypeScript、Manifest、图标及字体检查。

浏览器验证的是本地侧栏页面的布局。真实 Chrome 宿主的拖动体验，以及各操作系统原生打印，仍应在重载扩展后人工核对；不把本地页面检查当作真实扩展运行证明。
