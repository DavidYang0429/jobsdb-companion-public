# JobsDB 求职工作台

Chrome Manifest V3 扩展，提供岗位归档、多投递表、主简历、Gemini／DeepSeek 受限改写、独立简历快照、直接下载 PDF、原生打印和可选 Google Sheets 单向同步。无需自建服务器或登录产品账号。

当前为首个本地版本。构建、自动化测试及 Codex 内置浏览器的本地流程已验证；真实 Chrome 扩展加载、模型账号与 GAS 部署仍待完成；直接下载 PDF 已补充三语言单／双页文件检查，详见 [验证记录](docs/verification/2026-10-16.md)。

## 开发与构建

需要 Node.js 22.12+（本机已使用 Node 24.11.1）。

```sh
npm ci
npm run test
npm run build
npm run dev
```

网页预览地址为 `http://127.0.0.1:5173/src/dashboard/index.html`，侧栏布局为 `http://127.0.0.1:5173/src/sidepanel/index.html`。预览使用独立本地数据，不与扩展共享；采集和模型连接须在扩展中验证。开发服务器只监听本机。

`npm run build` 执行 TypeScript 检查、生成生产页面和后台／采集脚本，再检查 Manifest 入口、GAS 文件和 16／48／128 PNG 像素尺寸。产物位于 `dist/`，最低 Chrome 120，无需另外运行后端。字体及许可证随产物离线打包。

## 加载扩展（需在支持扩展的 Chrome 中自行操作）

1. 打开 `chrome://extensions`，开启开发者模式，选择“加载已解压的扩展程序”，选中本项目的 `dist` 文件夹。
2. 点击工具栏图标打开侧边栏；侧栏“打开全屏工作台”进入完整界面。
3. 已打开的 JobsDB 标签需要刷新一次以注入采集脚本。打开岗位后提取、核对、保存；身份不明确时不会自动拼接页面字段，可以手动录入详情链接和 JD。
4. 在主简历中填入真实资料并保存，或上传 PDF／DOCX／TXT，在本地提取文字后配置 Key 进行 AI 自动填表。识别稿须人工核对并保存。
5. 从岗位制作简历，查看原文对照、编辑和选择显示项。确认事实后保存独立版本，点击“下载 PDF”直接取得文件；“打印…”保留系统打印入口。直接下载支持英文、繁中和简中，使用嵌入字体及可复制文字，保留显示项、顺序和分页设置。页面语言切换不会自动翻译手工正文。

当前站点在本次观察的浏览器会把搜索卡片打开为独立岗位页，并移除搜索路由上的 jobId；分栏路由支持有样本测试，但未取得真实分栏页面验收。无岗位级 JSON-LD 的详情页使用 DOM，详情内 Apply 链接用于核对岗位身份。

## AI 设置

用户自填 Gemini 或 DeepSeek API Key；不会自动切换 Provider、重试收费请求或在后台上传简历。模型鉴权、429、超时、拒答、截断和结构错误均应明确提示。连接测试反馈服务商、请求模型，以及 Gemini 的 modelVersion 或 DeepSeek 的 model；接口没有返回模型标识时明确说明，不以模型自报身份代替服务端元数据。

初稿的 Gemini 2.5 默认值已调整为 `gemini-3.5-flash-lite`。原因是 [Google 当前模型目录](https://ai.google.dev/gemini-api/docs/models) 对新项目建议使用新模型，并限制新用户访问 2.5；模型字段可编辑，不承诺当前账号具备对应免费额度。DeepSeek 默认 `deepseek-chat`，仍需真实账号连通性验证。

使用前请自行确认供应商条款与数据处理规则。本地优先描述存储与可用性，AI 调用时内容仍发送至所选服务。

## Google Sheets 配置

完整脚本在 [gas/Code.gs](gas/Code.gs)，也可从设置页复制。脚本不会自动部署或修改任何真实表格。

1. 在自己的 Google Sheets 中进入 Apps Script，粘贴脚本。
2. 在项目设置的脚本属性中填写 `SPREADSHEET_ID`、`SHEET_NAME`（默认 `JobsDB`）、`TARGET_ID`、`SHARED_SECRET`。
3. 在扩展设置生成目标 ID 和至少 24 字符共享密钥；把相同值填写到脚本属性中。不要将密钥粘贴到表格单元格、URL 或版本库。
4. 部署为 Web App，以拥有者身份执行并完成授权，访问范围需允许扩展请求。若组织策略禁止所需部署方式，保留本地使用。复制正式 `/exec` URL 到扩展设置并启用同步。
5. 本地新增、备注、状态及分类改名进入队列。按记录 ID 与版本幂等更新，只有可读业务确认匹配时才显示已同步。断网与不确定结果最多自动尝试 5 次，失败后可手动补推。
6. 更换电子表格或目标地址须配对新的目标 ID；编辑脚本后发布新的部署版本。远端人工编辑不回写，插件管理列可能被后续推送覆盖。

接入前应使用空测试工作表验证写入、重复请求、响应丢失和权限；自动化使用 GAS 服务模拟器，不代表 Google 实际部署已通过。

## 数据与恢复

- 同一分类下重复录入定位已有记录；跨分类分别跟踪。投递进度不受重新生成简历影响。
- 主简历、投递表与完整简历版本保存在 `chrome.storage.local`。默认按 10 MB 配额处理，80% 提示备份，失败不会显示“已保存”。
- 完整 JSON 备份包含主简历、分类、岗位和历史简历，不含配置与密钥；Excel／CSV 只导出筛选后的职位表。
- 恢复校验结构、资源版本和引用，预览后只允许写入空数据集；不会自动清空或合并已有数据。恢复后需要重新配置外部服务。
- 历史简历使用自身的完整渲染快照，修改会另存版本。修改模板、字体或排版规则时必须增加版本并保留原资源，不能静默改变历史版式。
- 卸载扩展会清除本地数据。Sheets 仅为职位镜像，无法替代完整备份。

## 项目结构

- `src/ui/`：侧栏与全屏共用的 React 界面、主简历编辑器、简历工作室和设置。
- `src/background/`：受信消息入口、统一串行写入、采集转发与恢复同步。
- `src/content/`：JobsDB 身份校验与 DOM／JSON-LD 提取、页面快捷按钮。
- `src/services/`：存储、备份、结构校验、模型适配与同步协议。
- `gas/`：需要用户自行部署的 Google Apps Script。
- `tests/`：存储与并发、采集、模型、同步、GAS 模拟及后台消息集成测试。
- `需求排期/`：产品需求、技术规格与当前实现快照。

本阶段源码保存在公开 GitHub 仓库 [DavidYang0429/jobsdb-companion-public](https://github.com/DavidYang0429/jobsdb-companion-public)，使用 `main` 分支；扩展 ZIP 作为阶段预发布附件提供。尚未部署生产服务或发布到 Chrome 网上应用店，真实扩展及外部服务验收边界见上文与验证记录。

PDF 导出字体固定在 public/fonts/pdf-v1，完整嵌入以避免裁剪缺字。纯英文文件使用较小的 Inter 字体；包含中文的文件会较大。变更导出排版或字体须增加 pdfExportVersion，保留旧资源。


## AI 定制失败时怎么处理

岗位下方会保留原因、操作步骤和按钮，不再只弹出技术错误。

| 提示 | 下一步 |
| --- | --- |
| AI 生成的总结没有附上依据 | 通常是本次模型漏填。先点“重新生成”；仍失败可“手工制作简历”。无需自己改编号。 |
| 主简历没有可用于定制的内容 | 点“去完善主简历”，填写真实总结、技能、教育或经历并保存，再点“返回刚才的岗位”。空资料会在请求模型前被拦截。 |
| 数字需要核对 | 提示会指出经历、要点序号和数字。进入“编辑”删除或改成原文数字；新增真实成果需先补充并保存主简历。 |
| 技能新增或重复 | 提示会列出具体技能；不要为了通过检查添加不会的技能，可重试或手工制作。 |
| 连接、额度或输出格式异常 | 根据提示检查模型设置或稍后重试。每次重试都由用户主动点击，不自动重复调用。 |

原文对照展示具体总结、技能、教育、经历等资料；用户不需要编辑内部来源编号。


## 侧栏显示

侧栏内容宽度上限为 520px，较窄时随面板缩小；已检查 320px 和 390px。岗位表在侧栏使用卡片，简历工作室可切换“编辑简历／查看预览”，切换保留未保存内容。预览按宽度缩放，下载仍为 A4。全屏工作台保留宽表格及适合大屏的布局。

这限制内容区域，不锁定 Chrome 侧栏外框。更新构建后需在扩展管理页重新加载插件并刷新 JobsDB 页面。验证详情见 [侧栏布局记录](docs/verification/2026-10-16-panel-layout.md)。

## 上传已有简历与插件使用说明

“主简历底座 → 上传简历，自动填表”支持 PDF、DOCX、TXT。本地提取文字无需 API Key；点击“AI 识别并填入表单”需要设置中当前 Gemini／DeepSeek 的 Key，只发送展示的原文。先核对文字，再核对填入的表单，勾选确认并保存才更新整份主简历；不自动合并旧字段，可用“返回原表单”恢复识别前的手工编辑。

限制为单文件 10 MB、PDF 20 页、原文 50,000 字符；没有 OCR，扫描／图片 PDF 请改用文字版 PDF、DOCX 或粘贴正文，旧版 DOC 请先另存 DOCX。文件不发送到外部，也不写入备份，最终保存的结构化主简历沿用原存储与备份机制。PDF 读取 Worker、字体映射和标准字体随构建离线打包。

导航新增“使用说明”，覆盖首次加载与更新、主简历导入、API Key、采集与投递表、简历审核与下载、模型错误、Sheets、备份恢复和网页预览边界。验证见 [上传简历与说明记录](docs/verification/2026-10-16-resume-import.md)。

## 投递进度与时间

投递表显示“加入时间、投递时间、面试时间”。加入时间沿用归档时刻；点击岗位，在“投递与面试时间”按本机时区填写日期和时分，再点“保存时间”。投递／面试时间可以修改、清空，面试时间用于最近一次或下一次面试，不记录多轮历史。切换状态不会自动填时间，旧记录缺失日期保持空白。

状态为待投递、已投递、等面试、面试中、已拿 Offer、已失败、无回应；原“已淘汰”记录显示为“已失败”，内部值兼容旧数据。状态筛选、Excel／CSV、JSON 备份恢复和 Sheets 同步均保留这些字段。Excel／CSV 时间使用本机时区，Sheets 使用带 Z 的 UTC 时间；空时间为空单元格。

已部署 GAS 的用户需要复制新版脚本并发布新部署版本，才能同步新字段／状态。新脚本接受旧队列，只在旧 17 列表头完全匹配且新增列没有内容时追加 appliedAt、interviewAt 两列；发现自定义内容则拒绝覆盖。没有部署或操作任何真实表格。详见 [验证记录](docs/verification/2026-10-16-tracking-times.md)。


## 保存时出现旧版本校验错误

若保存简历提示不认识 pdfExportVersion，当前版本已支持此字段，通常需要更新实际运行的插件后台。先保留未保存的编辑，到 chrome://extensions 点击本插件的“重新加载”，关闭旧侧栏／工作台，再重新打开保存。无需卸载。新版在写入前检查前后台契约，版本不一致时会给出上述步骤。投递和面试时间均为选填，可以全部留空，不影响简历保存。

## Excel 与 CSV 导出

投递表的“导出格式”默认 Excel（.xlsx），可改选 CSV，点击“导出投递表”下载当前筛选结果。两者都有职位、公司、分类、状态、链接、备注、加入时间、投递时间、面试时间九列；不导出主简历、历史简历或配置密钥，不替代完整 JSON 备份。

Excel 为本地生成的 OOXML 工作簿，带表头样式、冻结首行、筛选和列宽。业务文字按文本写入，公式样式文本不会执行；日期为本机时区的 Excel 日期值，未填写时间为空单元格。单元格超出 Excel 的 32,767 字符限制时明确拒绝，提示使用 CSV 保留全部原文，不静默截断。CSV 保留原有 UTF8 BOM、引号／换行及公式保护。

109 项测试、生产构建和内置浏览器实际下载通过；下载的 XLSX 已用独立 openpyxl 读取核对字段、时间、空值、冻结／筛选与无公式。未在实际 Excel／WPS 中打开验收。详见 docs/verification/2026-10-16-excel-export.md。
