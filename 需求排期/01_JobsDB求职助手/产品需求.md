# 产品需求文档（PRD）：香港 JobsDB 求职助手 Chrome 插件

> 修订日期：2026-10-16。状态：首版本地实现已完成，真实扩展与外部服务联调待完成。用户已明确授权开始实现。

## 一、需求背景

香港求职者浏览 JobsDB 时，需要反复复制岗位、维护投递表和调整简历。本产品采用 Chrome Extension Manifest V3 + Side Panel，减少这些重复操作；不自建后端和账号体系，数据以本地为准。

## 二、目标用户与场景

首期服务用户本人，在 JobsDB 搜索分栏或独立详情页逐条筛选岗位、手动完成投递。浏览器插件负责采集、归档和简历准备，不代表用户提交申请。当前尚无用户调研或效率基线，不将预期收益写成已验证结论。

## 三、产品目标

打通“确认当前岗位 → 保存本地 → 定制并人工审阅简历 → 打印 PDF”的闭环。Google Sheets 作为可选的单向职位镜像，AI 和同步不可用时，仍可录入岗位、手动维护和打印简历。

## 四、功能范围

| 本期包含 | 本期不做 |
| --- | --- |
| JobsDB 双页面采集、人工修正、本地多投递表 | 无人值守批量海投、跨招聘站适配 |
| 主简历表单、AI 文本解析、受限改写及人工审核 | AI 自动新增经历、自动认定签证资格 |
| 英文／繁中／简中简历、编辑预览、直接下载 PDF／原生打印 | 自动静默保存 PDF、保证所有 ATS 解析一致 |
| Gemini／DeepSeek 可切换、用户自填 Key | 自建账号、数据库和代管模型密钥 |
| 可选 GAS 单向同步、完整本地备份与恢复 | Sheets 反向同步、多设备自动合并、云端完整简历备份 |

## 五、核心流程

1. 在当前 JobsDB 页面提取，校验岗位 ID 与详情一致，展示标题、公司和 JD 供确认。
2. 选择投递表并保存；本地持久化成功才显示“已保存”，失败保留编辑内容并提示重试。
3. 手工维护主简历，或将现有文本交给 AI 解析后逐项确认。
4. 基于当前岗位生成改写建议，显示原文对照；人工编辑、勾选和确认后保存独立简历版本。
5. 从该版本进入 A4 打印预览，用户在系统打印对话框选择保存 PDF。
6. 若已配置 Sheets，本地变更进入待同步队列；同步失败不影响前五步。

## 六、功能详细要求

### 1. 岗位提取与要求识别

- 支持搜索分栏和独立详情页。现有 URL、DOM 选择器和 JSON-LD 可用性均须实测，详见代码现状快照。
- 字段：来源、岗位 ID、标题、公司、地点、薪资、工作类型、标准链接、JD 纯文本及段落。薪资等未提供时标记“未注明”，不猜测。
- 采集绑定标签页和岗位 ID。快速切岗、页面加载中、详情与 URL 不一致时，不得保存混合数据；提取失败允许手动补录。
- AI 要求识别由用户主动触发。签证和语言要求须附 JD 原文依据；未写明则显示“未注明”，不得推导为接受 IANG 或提供担保。
- 核心关键词可提取 8～12 个；匹配分仅作模型参考，附依据和差距，记录主简历版本，简历更新后标记旧分析需刷新。

### 2. 本地投递表

- 分类使用稳定 ID，改名不改变记录归属。同一岗位在同一分类重复录入定位到已有记录，不覆盖备注或投递进度；允许同一岗位进入不同分类并独立跟踪。
- 投递进度：待投递、已投递、面试中、已拿 Offer、已淘汰。简历状态单独展示，重新生成简历不改变投递进度。
- 支持分类筛选、搜索、备注编辑、投递进度更新、历史简历查看及手动补推。
- CSV 用于职位表导出；完整 JSON 备份包含分类、职位记录、主简历和全部简历版本。备份默认不含 API Key、Webhook 和共享密钥。
- 恢复前校验版本、结构和关联，先预览；本期采用向空数据集恢复，不提供隐式覆盖、清空或自动合并。恢复后重新配置外部服务，不沿用已同步标记。
- 展示存储容量；配额不足时保留未保存内容并提示导出，不自动删除历史数据。卸载扩展会清除本地数据，职位镜像不能代替完整备份。

### 3. Google Sheets 单向同步

- 本地为唯一数据源；远端为同一电子表格内的一张固定明细工作表，以分类列区分本地投递表。远端人工改动不回写，后续同步可能覆盖插件管理列，须在接入说明中明确。
- 用户复制完整 GAS 模板，完成授权与部署，并配置 Web App URL 和独立共享密钥；不承诺脚本行数、配置用时或绝对稳定。
- 新增记录、修改状态／备注和分类改名均触发相关记录同步；按记录 ID 幂等新增或更新，重复请求不增加重复行。
- 展示未配置、待同步、同步中、已同步、失败状态。只有远端确认当前版本已写入才显示已同步；本地再次编辑立即回到待同步。
- 队列持久化，关闭面板或重启浏览器后可恢复。网络失败有限重试，鉴权或配置错误停止自动重试，允许用户修复后手动补推。
- 只发送职位跟踪字段，不发送主简历、简历正文、模型 Key 或本地配置。

### 4. 主简历、AI 改写与历史版本

- 主简历包含联系方式、签证状态、教育、工作、项目、技能和语言；每次保存增加版本号。
- AI 解析结果先成为待确认草稿，不直接覆盖主简历。事实缺失时留空，不自动补全。
- 改写只允许选择已有经历、润色有来源的要点和重排已有技能。公司、职位、日期、学历、签证信息从原始数据装配；新数字、年限、技能和资质不得自动写入。
- 展示原文／建议对照和来源。JSON 结构校验不等于事实真实，最终简历必须经过人工审阅。
- 主简历或岗位在生成期间变化，旧响应标记过期，不覆盖新内容；模型切换不允许旧请求串写。
- 每份定制简历保存完整渲染数据、人工修改、显示项、顺序、语言、来源版本、模板与排版版本。以后更改主简历不得改变旧简历；再次编辑历史简历另存新版本。

### 5. PDF 与模型配置

- 使用单栏、文字可选择的 A4 模板，支持单页和双页、逐项隐藏及分页预览。中英文字体随扩展打包并固定版本，打印前等待字体加载。
- 用户确认并保存简历版本后，点击“下载 PDF”直接生成带嵌入字体的 A4 文件；“打印…”保留原生打印对话框。直接下载使用姓名、岗位和公司生成安全文件名，保留显示、排序和分页设置。三语言单／双页须验证实际文件的显示与文本提取，不承诺所有 ATS 均可正确解析。
- 保留 Gemini 免费 API 测试路线与 DeepSeek 适配，支持设置模型和测试连通性；不自动切换 Provider 或发送第二次收费请求。
- 模型名作为可编辑配置，不承诺速度、免费额度或固定成本。测试连接反馈必须包含服务商、请求模型和服务端返回模型；接口未返回模型标识时如实提示。测试期间冻结本次配置，不能把之后改选的模型误显示成测试结果。
- **已确认决策（2026-10-16）**：用户知悉并接受真实简历调用 Gemini 免费 API 的数据处理风险，不将此作为开发阻塞项，不强制改为付费服务。该决定仅适用于用户本人，不代替未来其他用户的选择，也不表示服务商条款发生变化。
- 本地优先不等于不向外发送数据；模型请求只在用户触发相应功能时发起。不把已确认事项改造成反复确认流程。

### 用户测试补充：AI 失败时的操作引导（2026-10-16）

AI 定制错误须区分“缺少可用主简历资料”和“模型生成结果不合规”。每条错误提供原因、具体修正位置／步骤和可点击入口；不把修改内部编号或数据格式交给用户。资料不足时在调用前提示填写示例和保存路径；模型遗漏依据时明确属于本次生成问题，可显式重试或手工制作。重试不得自动发生。

已有个人总结、技能、语言和签证事实可作为总结依据，与经历和学历一起传给模型；没有依据时仍拒绝生成结果，不自动补造引用。数字核对须指出具体字段／经历要点和数字；原文对照须展示实际内容。


### 侧栏宽度与显示（2026-10-16）

侧栏内容上限 520px，适配 320px 起的窄面板；岗位列表以卡片展示，按钮、字段和弹窗不得撑出页面。简历编辑与预览分开切换，切换不能丢失未保存内容；屏幕预览缩放不得改变下载的 A4 尺寸。全屏工作台保持适合大屏的布局。浏览器外框宽度不属于本次可锁定范围。

## 投递表状态与时间补充（2026-10-16）

- 用户要求补充加入、投递、面试时间，以及已投递、等面试、已失败、无回应等状态。加入时间沿用 createdAt，只读；appliedAt、interviewAt 为可选 UTC ISO 时间（null 表示清空），界面按本机时区填写与显示到分钟。旧记录不推断或自动补日期，切换状态也不自动填时间。
- 状态为 saved／applied／waiting_interview／interviewing／offer／rejected／no_response，界面分别是待投递、已投递、等面试、面试中、已拿 Offer、已失败、无回应。rejected 仅改显示名称，兼容旧记录。筛选、列表及 CSV 同步更新。
- 点击岗位，在“投递与面试时间”编辑并保存；保留乐观并发版本校验。保存失败保留输入，记录版本变化后阻止旧草稿覆盖。主简历／历史简历逻辑不变。
- RecordSchema、PayloadSchema 和 CommandSchema 增加可选时间字段，projectRow 只在字段存在时加入，避免改变旧同步任务 payload 哈希。JSON 备份恢复自动保留新字段，无字段的旧数据依然可用。
- GAS 保持协议 v1 并兼容旧 payload；尾部追加 appliedAt、interviewAt。只对精确旧表头且目标列完全空白的表扩展，已有自定义列内容时返回 HEADER_MISMATCH，不覆盖。已部署用户需更新并重新发布脚本。
- 本期只保存一个面试时间，不新增多轮面试历史、提醒或自动认定无回应。92 项测试、生产构建及内置浏览器 320px 布局检查通过；未更新真实表格或部署扩展。详细证据见 docs/verification/2026-10-16-tracking-times.md。


## 保存版本错配与时间选填（2026-10-16）

用户反馈保存简历时出现 layout.pdfExportVersion 的 unrecognized_keys。当前源码和生成的后台都已包含该可选字段，因此旧插件后台／页面混用是疑似原因，未声称已复现用户 Chrome 的真实运行版本。新增 src/services/runtimeContract.ts：界面在写操作前向后台检查契约，后台也在命令解析前校验；不同版本拒绝写入并提示保留草稿、在扩展管理页重新加载、关闭旧侧栏／工作台后重开。旧校验错误也转换为相同步骤。不丢弃 pdfExportVersion，不放宽结构校验，不自动重载或卸载。

投递时间和面试时间均明确标注“选填”，可全部为空、只填一项或清空后保存，不影响保存简历与状态修改。数据仍是可选／nullable，无自动填充。

99 项测试通过，包含真实打包后台消息入口保存 pdfExportVersion、时间留空、持久化回读，以及新旧后台契约拒绝与原有 92 项。生产构建通过。未重载用户真实扩展，需在真实 Chrome 中重新加载产物后验收。
